## 完整目标与边界

以 `main` 的登录、focus、smart-calendar、rescue-comparison、team、emotion-energy、profile/settings 视觉与交互为参考，以 React 19/TypeScript/Tailwind v4 重写 Web，以 Go/Chi/Huma/PostgreSQL 实现对应保留业务。按 V2 五视图收敛；不迁回旧 iframe/router.js、微任务积分、目标树、爬虫、蓝牙调试或 501 占位接口。Android 的 Kotlin/Compose 客户端与穿戴采集属于此前全端计划，本轮按用户指令停止推进。

## 文件所有权与数据流

- Web：`apps/web/src/features/{auth,focus,calendar,team,energy,settings}`；共享原子组件在 `components/ui`，壳层在 `components/shell`，仅 API 生成类型作为传输模型，TanStack Query 管理服务端状态。
- 服务端：`services/server/internal/{auth,biometrics,schedule,workspace,realtime,api,db}`；`cmd/api` 显式装配处理器。沿用现有 DTO，必要变更同步导出契约。
- 算法：`services/server/internal/engine`，纯函数实现既定三个引擎；不访问数据库或网络。
- Android：`apps/android/.../core/{datastore,database,health,ble,network,ui}` 与 `feature/{schedule,team,energy,settings}`，不另写调度算法。
- 历史参考页、截图及临时工具放 `.appdata/`，不作为生产源码；可复用字体、品牌图标作为静态资源并记录来源。
- 原始生理数据 → 个人精力推理 → 隐私投影 → 团队推荐；救援/会议必须经明确确认、事务落库和并发校验。
