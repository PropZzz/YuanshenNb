## 0. 已确认的前提决策

1. **保留 Web 开发进度，不重建原生客户端。** `web/` 中的 25 个页面、6.4k 行 JS、34 个 Node 工具测试、11 个 Playwright 浏览器回归全部继续维护。
2. 旧 Flutter 客户端（含 398 个测试、5 个平台工程、Dart/Python 双端对拍）已于 2026-11-16 移出至 `../_cleanup-backups/flutter-retired-20261116-184458/`，**不恢复**。
3. 移动端形态以 **PWA** 补齐；只有在 W6 决策点评估 PWA 确实不够时，才用 Capacitor 壳复用现有 web 代码，不重写页面。
4. 调度内核视为**冻结资产**：`backend/scheduling/` 的排序规则、解释码和 `contracts/scheduling/v1/` 的 13 个向量不再改动，只做回归守护。

判断依据：现有页面已按 780px 断点做响应式适配（`web/index.html` 内联媒体查询），`manifest.json` 与 `tools/build_stitch_web.mjs` 已具备打包基础。重建原生需要重写 398 个已删测试并重建双端对拍，代价与本阶段收益不匹配。

## 2. 分工原则：按文件所有权切，不按功能名切

因为 25 个页面共用同一个 `router.js`，按「功能」分工会导致四人反复修改同一文件。因此按**文件唯一所有权**划分：每个文件只有一个写入者，其他人只能提 PR 由 owner 合并。

| 角色 | 唯一写权限 | 明确不碰 |
| --- | --- | --- |
| **P1 前端基座** | `web/index.html`、`web/stitch/router.js`、`page-host.js`、`actions.js`、`drawer-motion.js`、`time-picker.js`、`tools/*.mjs`、`tools/tests/` | 页面业务逻辑、后端 |
| **P2 页面业务** | `web/stitch/calendar.js`、`focus.js`、`profile.js`、`calendar-import.js`、`calendar-import-ui.js`、`screens/**`、`mobile/**`、`components/**`、`web/stitch/assets/**` | `router.js`、后端 |
| **P3 后端与数据** | `backend/**`（含 `scheduling/` 守护）、`contracts/**`、`deploy/*.py` | 前端任何文件 |
| **P4 质量与发布** | `backend/tests/**`、`tools/check_*.mjs`、`docs/**` 验收记录、`deploy/nginx*`、`deploy/ruanchuang-backup.*` | 业务实现（只开缺陷单，不代改） |

### W6 决策点

四人共同评估「PWA 是否满足移动端需求」，二选一：

- **够用** → 形态冻结，进入功能迭代。
- **不够**（需要推送、后台生理数据采集、应用商店分发）→ 只做 **Capacitor 壳**，复用全部 `web/` 代码，不重写页面。此时推送/设备能力解禁 `routers_reserved.py` 中对应接口。

## 4. 501 预留接口的处置顺序

按「用户可感知价值 ÷ 实现成本」排序，不按文档顺序：

| 优先级 | 接口 | 理由 |
| --- | --- | --- |
| P0（W2–W3） | `/reminders/*`、`DELETE /events/{id}` | 日程类产品缺提醒是功能缺失，不是增强 |
| P1（W6 后） | `/notifications/*` | 依赖 PWA 或原生壳，形态未定前不动 |
| P2 | `/sync/conflicts/{id}/resolve` + 客户端同步队列 | 需先有队列，当前不得在 UI 显示「待同步」 |
| P3 | `/files/*`、`/integrations/*` | 依赖对象存储与第三方授权，单独契约 |
| 冻结 | `/ai/*`、`/devices/*`、`/auth/password/reset*` | AI 与设备需专项数据集/授权；密码重置需邮件通道 |

**红线：** 任何 501 不得在 UI 伪装成成功；不得为预留接口写「假成功」适配。

## 5. 冲突预防三条硬规则

1. **单 owner 制：** `router.js` 与 `backend/repositories.py` 各只有一个 owner，其他人只能提 PR，由 owner 合并。
2. **每日文件预告：** 每天 10:00 同步「我今天改哪些文件」，P4 记录到当日验收文档；跨 owner 变更必须两人 pair 30 分钟。
3. **调度冻结：** 任何人不得修改 `backend/scheduling/` 的排序规则、解释码与 `contracts/scheduling/v1/` 向量。P3 只负责跑回归；P4 负责在报告中如实写明 parity 已断链。

## 7. 已知风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| `router.js` 拆分引入回归 | 25 个页面同时受影响 | 先补 Playwright 覆盖再拆；每个模块拆完立即跑 11 个回归 |
| 密码算法迁移锁死老账号 | 登录失败 | 保留旧字段惰性升级，迁移期双算法并存 |
| parity 断链被误读为通过 | 调度正确性失去证据 | P4 在验收文档明确标注「不可运行」，基准门禁保持阻断 |
| `build/` 2.5G 与 `_cleanup-backups/` 4.9G 污染仓库 | 克隆与检索变慢 | W1 内把 `build/` 加入 `.gitignore` 核查，备份目录移出仓库 |
| SQLite 单实例单 worker | 无法水平扩容 | 本阶段明确不做多实例；PostgreSQL 迁移放到 W6 之后单独评估 |
